4eNEXT to owlbear Owlbear Rodeo 插件 v1.3.0

在枭熊里看 4E NEXT 的「速览」页：右键 token 绑定角色卡，之后选中这枚 token 就会弹出速览。 v1.2.0 起还能在弹窗里直接加减血量（token 上会画出血条），并把威能 / 装备点掉记成「已用」； v1.2.1 把速览弹窗加宽到 660×700；v1.2.2 弹窗可以按住标题栏拖动、位置按 token 记住。 v1.3.0 改名「4eNEXT to owlbear」：面板变成「速览 / 先攻 / 骰子」三个 tab（骰子先占位）， 右键新增「加入先攻 / 隐形加入先攻」，绑定角色卡后先攻加值自动取卡里的「先攻」。 纯静态、免构建、不需要服务器。

这是什么

  • 速览面板：生命 / 血怒 / 回复力、AC 与三防、六属性、17 项技能、攻击与伤害、威能、专长、装备，全部来自 4E NEXT 的「导出存档（JSON）」。
  • Token 绑定：GM 右键地图上的 IMAGE token →「绑定 4E NEXT 角色卡」，选中卡之后，任何人选中这枚 token 都会看到速览。
  • 数据存房间：卡片存在 Owlbear 的 room metadata 里，全房间共享，没有自建服务器，也不需要账号。
  • 血量与资源追踪：速览弹窗里能 −1/−5/−10、＋1/＋5/＋10 或填数字改血，token 上会画出「当前/上限」血条； 威能 / 装备点一下变灰 = 已用，再点恢复；行动点与里程碑并成一排加减（专长只展示，不追踪使用）。
  • 三 tab 面板：速览 / 先攻 / 骰子；tab 切换只切显示，不重载页面。左上角 4E 图标直接打开「先攻」tab。
  • 先攻：右键 token →「加入先攻」或「隐形加入先攻」；先攻加值取绑定角色卡的「先攻」（如 +25），合计 = d20 + 加值。GM 可推进任意回合，玩家可「结束我的回合」（请求由城主客户端落笔）。隐形条目只有 GM 看得到。
  • 骰子（占位）：v1.5.0 才实现；本版 tab 里写明「即将推出」。
  • 改卡还是要回 4E NEXT：插件不改角色卡本身（威能选择、属性、装备都不动），只记录本场战斗的消耗。

三步部署（GitHub Pages）

  1. 把本目录（manifest.json、background.html、icon.svg、icon-tool.svg、assets/、data/、vendor/、samples/ 等）整个上传到一个 GitHub 仓库。
  2. 仓库 Settings → Pages：Source 选 Deploy from a branch，Branch 选 main / 根目录 / (root)，保存。
  3. 等 1 分钟，得到形如 https://<用户名>.github.io/<仓库名>/ 的地址，那么 manifest 地址就是它加 manifest.json。

也可以直接把仓库挂到 jsDelivr：https://cdn.jsdelivr.net/gh/<用户名>/<仓库名>@main/manifest.json（改一次推一次，CDN 会缓存几分钟）。

你的 manifest 地址

这个地址是当前页所在目录下的 manifest.json。把整包放到任意静态托管（GitHub Pages / jsDelivr / Netlify / 自己的网站）都能用。

在 Owlbear Rodeo 里添加扩展

  1. 打开 owlbear.rodeo/extensions（或在房间右上角菜单进 Extensions）。
  2. 点 Add Extension，把上面复制的 manifest 地址粘进去，确认。
  3. 回到房间，三个入口任选其一打开面板：左上角的 4E 图标（manifest 的 action，不依赖后台脚本）、左侧工具栏的 4E 工具按钮、右下角的绿色 4E 浮动按钮。右键地图上的图片 token 还会多出「绑定 4E NEXT 角色卡」（仅 GM）。

扩展是每个玩家各自安装的（房主装了自己也装）。插件的数据在房间数据里，所以别人装好后无需再导入。

使用流程

  1. 导出：在 4E NEXT 里打开角色卡 →「导出存档（JSON）」，得到一个 .json 文件。
  2. 导入：Owlbear 里打开面板（左上角 4E 图标 / 左侧工具栏 4E 工具 / 右下角 4E 按钮任选其一）→ 把 json 拖进去（或点「导入 JSON」/「粘贴」）。同名卡会被就地更新，绑定关系不丢。
  3. 绑定：右键地图上的角色 token →「绑定 4E NEXT 角色卡」→ 选一张卡（同时写入先攻加值）。
  4. 看速览：选中这枚 token，速览小面板就从 token 上方弹出来；点 ⤢ 可以打开完整面板。
  5. 打先攻：右键 token →「加入先攻」/「隐形加入先攻」；到面板「先攻」tab 推进回合。

绝对地址是按当前页面的域名算的，所以要在你最终使用的托管地址上打开本页再复制。目录里还留了一份可移植的 manifest.relative.json（相对路径版），但那需要宿主正确解析相对地址，不推荐。

GitHub Pages 项目页是子路径（/仓库名/）。相对路径的 manifest 在某些 Owlbear 版本里会被当成站点根目录，于是找不到 background.html：表现就是扩展列表里有这个插件，但房间里没有按钮、也没有右键菜单。用绝对 manifest 可以避开这个坑。

已知限制

  • 血量与资源状态不在导出快照里改：它们单独存在 token / 房间数据上，重新导入同名卡不会清掉。
  • 谁都能看，改的人有限：token 血量只有城主或这枚 token 的创建者能改（Owlbear 的 item 权限）；资源追踪写房间数据通常只有城主能写，玩家点了会退化成「只记在本机」。
  • 数值是插件离线推导的：职业特性自动加值（如信仰甲胄、蛮族机敏）和少数专长效果无法离线还原，可能和 4E NEXT 差 1~2 点，以 4E NEXT 为准。
  • 房间数据只有 GM 能写：玩家装好扩展能看，但导入/绑定要 GM 操作（Owlbear 对房间数据的权限限制）。
  • 卡片存在房间数据里：删掉扩展不会删数据；换房间要重新导入。
  • 先攻首版是简单列表：没有头像条、拖拽排序、隐藏条的镜头处理；只有名单 / 加值 / 合计 / 回合推进。
  • 没有在真实 Owlbear 房间里做联机测试（开发环境无法起 GUI）：只做了静态检查、假 OBR 的后台冒烟测试与本地渲染验证。 血条与先攻的交互都按参考实现（FullPeople/obr-suite）的 API 写法实现，真机效果仍需验证。

目录结构

manifest.json        扩展清单（Owlbear 加载的入口）
background.html      后台页：右键菜单 / 加入先攻 / 浮动按钮 / 选中 token 弹窗 / token 血条
button.html          右下角 4E 浮动按钮
panel.html           全屏三 tab 面板：速览 / 先攻 / 骰子（占位）
info.html            选中 token 时弹出的速览小面板
bind.html            右键「绑定」打开的选卡弹窗
index.html           本页（说明 + 示例）
assets/              渲染层与页面脚本、样式（glance.js 渲染、track.js 血量与资源读写、initiative.js 先攻）
data/rules.js        职业/种族/基础物品/装备等级索引（离线数据）
vendor/obr-sdk.js    @owlbear-rodeo/sdk 3.1.0 的 ESM 打包（本地化，离线可用）
samples/             示例卡（可删）
dev/                 开发期工具（普通用户用不到）

非官方作品，与 Owlbear Rodeo、4E NEXT 均无隶属关系。角色卡数据只在你自己的房间与浏览器里流转。
