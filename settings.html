关于

在 Owlbear Rodeo（枭熊）里看 4E NEXT 导出的角色卡速览：右键 token 绑定角色卡， 选中就弹速览，加减血量会画到 token 上，威能 / 装备点一下记成「已用」，先攻按卡里的加值推进。

插件名4eNEXT to owlbear 版本— 构建— 作者4E NEXT 玩家自制（非官方作品） 性质纯静态页面 + 一个后台脚本，无服务器、无账号、无构建步骤

这个版本的入口（一排按钮）

左上角扩展图标（角色卡 / 导入）、左侧工具栏的 速览 / 角色卡 / 先攻 / 骰子 / 设置 五个图标、右下角 4E 浮动按钮、右键地图 token。每个入口打开自己的窗口，可以同时开着、互不嵌套。

与 Owlbear Rodeo、4E NEXT 均无隶属关系；角色卡数据只在你自己的房间与浏览器里流转。

使用说明

  1. 导出：4E NEXT → 打开角色卡 →「导出存档（JSON）」→ 得到一个 .json 文件。
  2. 导入：打开「角色卡 / 导入」窗口（左上角图标 / 工具栏「角色卡」/ 右下角 4E 按钮）， 把文件拖进窗口、或点「导入 JSON」、或点「粘贴」贴上 JSON 全文。同名卡会就地更新，已绑定的 token 不丢。
  3. 绑定：在地图上右键一个图片 token →「绑定 4E NEXT 角色卡」→ 选一张卡（可搜索）。
  4. 看速览：选中这枚 token，速览小窗会从 token 上方弹出； 也可以点工具栏「速览」给当前选中的 token 开一次（没选中时会提示先选一个）。
  5. 打起来：在速览里点 −1 / −5 / −10 或 ＋1 / ＋5 / ＋10 改血， token 上的血条会跟着变；威能 / 装备点一下变灰＝已用，再点恢复；「长休」一键还原。
  6. 先攻：右键 token →「加入先攻」/「隐形加入先攻」（先攻条会自动弹出）→ 先攻条上「战斗准备 / 突袭 / 开始战斗」，再「上一回合 / 下一回合」推进；GM 任意推进，玩家点卡片上的「结束」。 要移出：右键已经在先攻里的 token →「移出先攻」，或点先攻条上 GM 卡片右上角的 ✕； token 被删掉时条目会自动清理，游标顺移到下一条。

窗口怎么用

  • 按住标题栏（左侧 ⠿ 那一条）可以把窗口拖到不挡地图的地方；每个窗口各自记位置（存在本机）。
  • 标题栏右上角的 ⌖ 清掉这个窗口记住的位置、回到默认点；速览小窗的 ⌖ 是「回到 token 上方」。
  • 窗口打开前会按视口尺寸夹紧，小屏 / 合盖后再打开也不会超出屏幕。
  • 窗口顶部有一条后台连接状态：显示「后台未连接，点这里重试」时，先点它重试； 仍然不行就打开插件根目录的 background.html 看自检日志。

入口一览

入口打开什么 左上角扩展图标角色卡 / 导入（由 manifest 的 action 提供，不依赖后台脚本） 工具栏「速览」当前选中 token 的速览（与「选中即弹」同一个窗口） 工具栏「角色卡」导入 / 列表 / 预览 / 绑定 工具栏「先攻」先攻条（战斗准备 / 突袭 / 一键清空 / 回合推进 / 拖拽排序） 工具栏「骰子」骰子（表达式 / 战斗优势 +2 / 重击取满 / 4E 预设 / 本次结果）；记录在它自己的「记录窗口」里（最近 4 条）+ 投骰动画 工具栏「设置」本窗口 右下角 4E 按钮角色卡 / 导入 右键 token绑定角色卡 / 加入先攻 / 隐形加入先攻 / 移出先攻（仅 GM；菜单随先攻名单动态变）

骰子

骰子窗口（工具栏「骰子」）只负责组公式和显示本次结果； 记录已经搬到它自己的窗口：可以拖动、单独记位置，和骰子窗口各自开关、可以同时开着。

投骰动画

每次投掷后，在选中 token 的头顶（没选中时在屏幕中央）出现放大的骰子： 飞入 → 落地读数 → 放大一下 → 淡出，约 2.6 秒。动画层不挡鼠标，播放期间照样能平移 / 选中地图； 骰子的点数是这次的真实结果（先算完再播）。

当前状态—

关掉之后投掷照常、结果照常显示在骰子窗口的「本次结果」里，只是不再弹出动画。 这是本机设置（只影响这台电脑 / 这个浏览器）。

记录窗口

  • 骰子窗口里的 「记录窗口」 按钮打开 / 收起它；按住它的标题栏可以拖走，位置单独记住。
  • 默认只显示最近 4 条，点「展开全部」看全部（最多 20 条，列表内滚动）。
  • 与骰子窗口是同一份数据（房间数据 com.4enext-owlbear/rolls，城主客户端落笔）： 20 条封顶，超出时自动删最旧的那条。
  • 清空记录仍然只在骰子窗口里、且只有城主能做（要点两次）。

先攻

先攻条（工具栏「先攻」）从 v1.7.3 起是常驻的：进入房间就自动出现在屏幕顶部， 点地图不会把它关掉；卡片区右侧不再铺深色底，条的背景是透明的（地图能透出来）， 只有卡片自己是深色底。

进入房间自动显示

当前状态—

这是本机设置（只影响这台电脑 / 这个浏览器）。关掉之后仍然可以从工具栏「先攻」 或右键「加入先攻」随时打开。条右上角的 「—」只是最小化（折叠成 120×40 的小药丸，药丸也常驻）； 「✕」才是真正关掉 —— 关掉后本次会话不再自动弹，重新打开一次就恢复。

骰子记录窗口

当前状态—

v1.9.2：本机设置，默认开。进入房间后约 0.8 秒自动打开骰子记录窗口； 记录窗口的 ✕ 关掉后本次会话不再自动开（刷新 / 重新进房间自然恢复）。骰子窗本身由 OBR 左上角按钮管理，不受这里影响。

从先攻里移出

  • 右键已在先攻里的 token →「移出先攻」（菜单是动态的：不在先攻里时显示「加入先攻 / 隐形加入先攻」）。
  • 先攻条上 GM 的卡片右上角有 ✕：点一下直接移出（不用开列表窗口）。
  • token 被删除后，先攻条里对应的条目会自动清理，游标顺移到下一条（不会卡在一个已经不存在的单位上）。

数据与权限

没有自己的服务器：角色卡与战斗状态存在 Owlbear 的房间数据里（全桌共享）， 单枚 token 的血量存在 token 元数据上，窗口位置这类「只跟我这台机器有关」的东西存在 本机 localStorage。

骰子动画

动画速度（每个客户端独立）。关闭 = 只显示结果，约 0.5 秒。

房间数据（同房间所有人可见，通常只有 GM 能写）

键内容 com.4enext-owlbear/cards角色卡列表（导入的 JSON 精简后） com.4enext-owlbear/state/<cardId>威能 / 装备「已用」、行动点、里程碑 com.4enext-owlbear/initiative先攻状态（阶段、回合、名单、顺序、d20 / tiebreak、隐形标记） com.4enext-owlbear/rolls骰子历史（团队共享，最多 20 条；只有城主客户端能写）

清理房间数据（房间数据上限 16 KB）

房间数据装不下时，加入先攻 / 改先攻加值 / 回合推进 / 骰子历史落库都会写不进去 （真机报错：Unable to update metadata: over size limit of 16 kB）。 这里能看到当前用量，一键清掉骰子历史或角色卡就能腾出空间。

当前用量正在读取… 角色卡— 骰子历史— 先攻条目— 其它插件占用— 占用排行— 实际来源—

两个清理按钮都要点两次才真的清（第一次只是「预备」，5 秒内不点第二次就自动取消）。 只有城主能改房间数据；角色卡是双写：房间数据存精简名单副本（跨场景可见、用于绑定）， 当前场景的隐藏 item 存完整卡（面板写「角色卡：本场景」）；两边都写不进才兜底本机（「角色卡：本机」）。

Token 元数据（写在自己那枚 token 上）

键内容 com.4enext-owlbear/cardId绑定的角色卡 id com.4enext-owlbear/hp{ cur, max, temp, surges }：这枚 token 的血量快照 com.4enext-owlbear/init{ bonus, cardId }：先攻加值 com.4enext-owlbear/in-inittrue / false：这枚 token 在不在先攻名单里（v1.7.3，右键菜单据此显示「移出先攻」还是「加入先攻」）

本机 localStorage（只影响这台电脑 / 这个浏览器）

键内容 4enext/win-pos各独立窗口的位置（按窗口名） 4enext/info-pos速览小窗的位置（按 token id，最多 40 枚） 4enext/state/<cardId>房间数据写不进去时的追踪降级副本 4enext/cards-local场景也写不进时的最后兜底副本（v1.8.0；面板上写「角色卡：本机」） 4enext/dice/combos骰子组合（最多 30 条） 4enext/dice/last上一次掷过的骰子公式 4enext/dice/local旧版「城主离线时的骰子暂存」（v1.9.2 起并入本机历史，启动时迁移） 4enext/dice-history/<roomId>骰子历史（v1.9.2：本机保存、按房间隔离、最多 20 条；不再写房间数据） 4enext/strip-autostart进入房间是否自动显示先攻条（v1.7.3，"0" = 不自动显示，缺省开） 4enext/strip-closed-this-session本次会话是否手动关过先攻条（v1.7.3，关掉后本次不再自动弹） 4enext/dice-hist-autostart进入房间是否自动打开骰子记录窗口（v1.9.2，"0" = 不自动打开，缺省开） 4enext/dice-hist-closed本次会话是否手动关过骰子记录窗口（v1.9.2，关掉后本次不再自动开）

权限差异

操作谁能做 导入角色卡 / 绑定 token城主（房间数据写权限） 改某枚 token 的血量城主，或这枚 token 的创建者 标记威能 / 装备已用优先写房间数据（通常只有城主）；写不进去就只记在这台机器上 加入先攻 / 推进回合城主；玩家可以「结束我的回合」，由城主客户端落笔 隐形先攻条目只有城主看得见，玩家连名字都收不到 骰子历史落库 / 清空城主（写房间数据）；玩家投掷只广播，城主不在线时结果只在本机

卸载扩展不会删除房间数据；换房间需要重新导入。自诊断通知的开关只影响提示，不属于上面这些键。

重置本机设置

只清这台电脑上的插件记忆，不碰房间数据、不碰 token 元数据、不碰角色卡。

会被清掉的

  • 4enext/win-pos：各独立窗口记住的位置（清完下次打开回到默认点）。
  • 4enext/info-pos：速览小窗按 token 记住的位置。
  • 4enext/state/*：追踪降级数据（房间数据写不进去时只记在本机的那份副本）。

不会被动的

  • 房间数据：角色卡列表、先攻状态、全桌共享的「已用」标记。
  • Token 元数据：绑定关系、血量、先攻加值。
  • 4E NEXT 导出的 .json 文件。
